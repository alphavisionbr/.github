# Security Policy

[Versão em Português](SECURITY.md)

Alphavision® takes the security of its projects and the community that uses them seriously.

If you identify a security vulnerability in any project maintained by Alphavision®, we ask that it be reported responsibly and privately before any public disclosure.

## Reporting a Vulnerability

To report a potential security vulnerability, please contact us at:

**contato@alphavision.com.br**

Whenever possible, please include:

- Name of the affected project or repository
- Affected version, when applicable
- Detailed description of the vulnerability
- Steps required to reproduce the issue
- Potential impact of the vulnerability
- Evidence, examples, or proof-of-concept code, when available

Please do not include sensitive information in GitHub Issues, Discussions, Pull Requests, or other public GitHub channels.

## Review Process

After receiving a security report, we will seek to:

1. Acknowledge receipt of the report.
2. Analyze and reproduce the reported vulnerability.
3. Assess its impact and affected versions.
4. Develop and test a fix when necessary.
5. Publish the appropriate update and guidance.

The time required for investigation and remediation may vary depending on the complexity and impact of the vulnerability.

## Responsible Disclosure

We ask that information about unresolved vulnerabilities not be publicly disclosed before we have had reasonable time to investigate and provide a solution.

After a fix is available, we may publish information about the vulnerability, affected versions, and recommended actions for users.

## Scope

This policy applies to public projects officially maintained by the Alphavision® GitHub organization.

Archived projects, third-party forks, or external software used as dependencies may be subject to the security policies of their respective maintainers.
